Running a case

One TOML file states everything a run needs, and is validated in full before anything is solved.

julia scripts/run.jl config/Cf252_sf.toml

config/Cf252_sf.toml is the annotated reference. Each key carries its allowed values or its bounds as a comment, and load_configuration enforces exactly what the comment says, naming the offending key when it cannot.

run_pipeline sweeps the fragmentation domain against the kinetic energy grid, solves the emission chain at every configuration the physics admits, contracts the result against the yield weights, and returns a RunResult. A configuration is dropped only where the physics excludes it — a non-positive TXE, a partition the segments do not cover, a fragment the mass table cannot reach — and the counts of attempted and solved configurations are written alongside the results, so the coverage of a run can be audited from its own output.

scripts/run.jl writes the result on the DrWatson layout. The tables go to data/sims/<system>/<run> through write_results, where the system is system_label and the run is run_identifier — savename over run_parameters — so two runs of one system that differ in anything the identifier covers land in different directories, and a directory name states what produced it. Beside the tables the script writes metadata.toml — run_metadata from the library, plus the identifier, the paths, the commit through DrWatson's tag!, and the platform — and copies of the configuration and the resolved Manifest.toml, so a result traces to configuration, commit, environment and hardware from its own directory. A directory that already holds a run is moved aside as <run>#1, <run>#2, … rather than overwritten.

DeterministicSequentialEmission.CONFIGURATION_KEYS — Constant
CONFIGURATION_KEYS

The sections a configuration may hold and the keys each may carry. Any other section or key is refused on load, so a misspelt optional key cannot silently take its default.

DeterministicSequentialEmission.Configuration — Type
Configuration

A complete run: the fissioning system, the fragmentation domain, the level density and evaporation models, the TXE partition, and the yield weights. Built by load_configuration from a TOML file; every field is validated on load, and a section or key outside CONFIGURATION_KEYS is refused. The output location is not a field: a run writes to the directory named by system_label, under the identifier built by run_identifier.

DeterministicSequentialEmission.RUN_IDENTIFIER_ABBREVIATIONS — Constant
RUN_IDENTIFIER_ABBREVIATIONS

The token each configuration key contributes to a run identifier. This table is the single source of abbreviations, so a directory name maps back to configuration keys. run_identifier throws for a key with no entry. One entry, kinetic_energy_bound, is not a key: it stands for kinetic_energy_limit and kinetic_energy_moments of [yield] together, "grid" or the moments restored under the physical bound.

DeterministicSequentialEmission.RunResult — Type
RunResult

What one run produced: the domain it swept, the averaged observables against fragment mass and against total kinetic energy, the totals, the prompt neutron spectrum where one was asked for, and the post-neutron product distributions where they were. run_pipeline produces it; write_results writes it.

Curves are Curves. The products, empty when [products] is disabled, are product_mass_yield (A_p, Y), product_yield (Z, A_p, Y) sorted by Z and then A_p, product_neutron_yield (N_p, Y), product_kinetic_energy (A_p, E_K_p), product_kinetic_energy_by_charge (Z, E_K_p) and product_total_kinetic_energy (A_p, TKE_p) keyed by the heavy product mass; mean_product_mass_loss, ⟨A − A_p⟩ per fragment, and mean_product_total_kinetic_energy are their totals, NaN when disabled. solved_mean_kinetic_energy and solved_kinetic_energy_dispersion are the mean and the pooled within-mass standard deviation of TKE over the configurations the sweep solved, the effective ⟨TKE⟩ and σ_TKE of the run; mean_kinetic_energy is the mean of the input yield over every cell it holds, solved or not. gamma_energy is the energy a fragment's neutrons leave, gamma_energy, against fragment mass; gamma_energy_total_by_mass and gamma_energy_total_by_energy are the sum over the two fragments of a split against the mass of either and against TKE, and total_gamma_energy its mean per fragment.

DeterministicSequentialEmission._pair_weight — Method
_pair_weight(fragmentation, yield) -> Float64

The weight of one fragmentation in a sum over pairs: the fragment yield of its heavy side times split_weight of the domain package, which halves every mass-symmetric entry so that the heavy-side sum is exactly half the sum over all fragments.

DeterministicSequentialEmission._write_charge_distributions — Method
_write_charge_distributions(destination, configuration, digits)

Write the isobaric charge distribution the run used, beside the alternatives, as up to four tables in the A dZ sigma_Z form of an evaluation. A Zₚ model is reduced at each heavy mass to the plain Gaussian of the same first two moments, the width being the rms on the charge lattice.

  • charge_distribution_vs_A.dat — the distribution charge_distribution_file selected.
  • charge_distribution_vs_A_wahl_per_reaction.dat — the Zₚ model of Wahl, At. Data Nucl. Data Tables 39, 1 (1988), doi:10.1016/0092-640X(88)90016-2, with this reaction's own parameters, where that evaluation covers it.
  • charge_distribution_vs_A_wahl_systematics.dat — the same model with parameters from eq. (17) of LA-13928 (2002), doi:10.2172/809574, where the system lies inside its fitted range.
  • charge_distribution_vs_A_mean.dat — the conventional means, without mass dependence.

These are the layers of charge_model. Where the run used one of the alternatives, the corresponding files coincide.

DeterministicSequentialEmission.run_identifier — Method
run_identifier(configuration) -> String

The token that names one run of one fissioning system: DrWatson's savename over run_parameters, tokens sorted and joined by _, every value rendered by one rule — integers and integer-valued reals without a decimal part, everything else as printed — so one grid has one spelling.

DeterministicSequentialEmission.run_metadata — Method
run_metadata(result) -> Dict{String, Any}

What the library knows about a run, as nested tables ready for TOML.print: "system", the fissioning system; "model", every modelling choice and input the configuration resolved; "result", the totals. The caller adds what only it knows — the run identifier, the paths, the commit, the platform — and writes the whole; scripts/run.jl does.

DeterministicSequentialEmission.run_parameters — Method
run_parameters(configuration) -> Dict{String, Any}

The configuration values that change the result, keyed by the token each contributes to the run identifier.

Every key is abbreviated through RUN_IDENTIFIER_ABBREVIATIONS; a key with no entry throws. The scalar and enumerated keys are covered, including incident_energy; deformed_branch appears only under Gilbert-Cameron, and total, symmetrize and kinetic_energy_bound only where a yield was loaded. kinetic_energy_bound is not a key of its own: it is "grid" where kinetic_energy_limit = "grid", and the kinetic_energy_moments restored where the bound is physical, so the two keys take one token. Not tokens, and recorded in the run metadata instead: the input files, the spectrum grid and maxwellian_temperature (which affect the tabulation, and through the grid the first moment in totals.dat, but not the solution), and significant_digits. The system names the directory containing the identifier.

DeterministicSequentialEmission.run_pipeline — Method
run_pipeline(configuration) -> RunResult

Solve every configuration the domain and the kinetic energy grid span, contract the results against the yield weights, and return the result without writing it; write_results writes the tables, and scripts/run.jl adds the provenance. The sweep is deterministic, with no sampling. A configuration is dropped where TXE is non-positive, the partition input does not cover it, or the mass table does not reach a fragment; the counts of attempted and solved configurations are reported with the result. The post-neutron product distributions are contracted from the same chains, normalised to the total of the input yield, [yield] total, or to DEFAULT_YIELD_TOTAL (200) where none was loaded.

source
DeterministicSequentialEmission.write_results — Method
write_results(result, directory) -> String

Write the tables of a run into directory: one two-column file per curve, the fragment yield projections, the post-neutron product distributions with the independent yields Y_vs_Z_A_p.dat in three columns, the charge distribution the run used beside the ones it could have used, and a table of totals.

directory is created. A directory already holding a run is refused, not overwritten; scripts/run.jl moves an existing run aside as #1, #2, …. The provenance record is written by the script, from run_metadata and its own additions.
